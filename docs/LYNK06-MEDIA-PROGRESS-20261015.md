# 领克原车媒体进度同步

初始实现日期：2026-10-15。当前状态更新：2026-10-17。

## 实现

- iAP2 收到有效位置时记录 `positionUpdatedAtNanos`；即使位置数值相同，也按新上报重新校准。
- 播放时使用单调时钟从已知位置外推，暂停时冻结。
- 播放/暂停状态变化未携带位置时保持连续；seek 或新位置到达时重置基准。
- 未知位置不外推；已知有效时长限制显示上界。
- 原车主动进度查询和主动进度事务使用同一计算结果。
- 原车媒体中心持有控制权、会话有效且处于播放状态时，每秒刷新一次进度。
- 定时任务只发送进度，不重发歌曲、列表或封面。
- 暂停、来源切换、失去控制权、断开和关闭后取消定时刷新；执行前后都重新检查控制权、服务和令牌。
- 标准媒体元数据比较忽略进度时间字段，避免只因时间推进就重复发布封面。

## 与歌曲列表的边界

进度更新与当前歌曲列表分离：

- 标题、歌手、专辑、时长或封面变化可以触发列表更新。
- 每秒位置变化不触发列表和播放信息重发。
- 标题式歌词变化可能改变歌曲 UUID，诊断会标记 `title-only-churn`，用于区分真实换歌。

## 自动化验证

回归覆盖：

- 位置基准保留与相同位置重新校准。
- 播放外推、暂停冻结和暂停后继续。
- seek、未知位置、有效时长边界。
- 原车查询与主动发送使用同一位置。
- 每秒刷新仅发送进度。
- 控制权丢失、来源变化、断开、关闭和迟到任务。
- 元数据补充时进度连续。
